# Shared-system standards

Status: accepted owner direction, 2026-09-11. New development must carry across its consumers. A preview is an adapter to shared systems, not permission to fork them.

## Rule

Each reusable capability has one implementation owner. Views translate their input state into that owner's contract, choose documented configuration, and handle camera/selection/UI. They do not reimplement behavior, copy tuning constants, or invent missing events in a live game. The server remains authoritative for orders, combat, visibility and persistence.

If a feature should work in two places, change the owner and both adapters in the same change. Differences must have a named reason and explicit configuration. “It is only a preview” is not a reason. Report unsupported features as gaps rather than describing a view as standardized.

## Production campaign consumer

The alpha at `/` is `BattlefieldApp` → `countrySliceScene` with a campaign roster, using the exact shared tactical presentation/audio/effect path. The scene's faction handling uses roster affiliation, not the old numeric four-friendly-unit cutoff. Scene-specific test controls stay in `countrySlicePreview`; the production API never calls `startEncounter`.

`advanceCountryCombat` owns continuous combat and is consumed by the country test (via its compatibility alias) and `advanceCampaign`. Only the country test supplies an encounter stage/deadline. Campaign territory/supply updates run on the same fixed steps. `campaignRuntime` combines immutable base sight with dynamic sandbag cover and builds navigation from the matching obstacles. `emplacementModels` supplies the same sandbag geometry to city construction and the campaign. `countryPlayerState` filters both consumers and feeds hidden reports through `createCityHearing` without exposing target IDs or exact unseen coordinates.

`countryLandscapeSamples` is memoized by immutable geography-plan identity. Consumers must not mutate its arrays; altered terrain/site/road geography requires a new plan. Dynamic obstacles do not change landscape samples. See the [campaign integration inventory](campaign-alpha-integration.md) for unconnected mechanics; the alpha does not imply all systems are standardized.

## Required feature workflow

1. Read this map and identify the shared owner before changing a view.
2. Search for every consumer and duplicate implementation, including previews, benchmarks, authoring galleries and saved-state adapters.
3. Define the input contract: coordinates, units, time, stable IDs, visibility authorization, supported roles and lifecycle. Supply missing authoritative events at the source.
4. Implement in the owner. Keep adapters limited to translation. Reuse cached geometry/poses and bounded effect resources.
5. Verify the same fixture through each affected adapter. Exercise both factions, pause/resume, death, reset, hidden-tab return and disposal when relevant.
6. Run applicable regression tests, typecheck/build and browser review of the affected views. Record observations separately from assumptions; automated PCM checks do not prove sound quality.
7. Update the ownership map, project state and session note. Final handoff names the consumers changed, validation and remaining gaps. Do not call a feature complete while a required consumer is missing it.

## Enforcement

`tests/tactical-presentation.test.ts` checks common city/country poses, fractional per-member playback, effect lifecycle, independent tracks, impact-event persistence and use of the shared owner by the two playable scenes. These are safeguards, not an exhaustive architecture proof: a new consumer must be added to the inventory and contract tests.

Do not create scene-specific substitutes such as permanent firing lines, snapshot-only recoil, footstep timers unrelated to distance, or hiding dead soldiers immediately. Do not silently omit audio because an event field is absent. Add the field/adapter, or record a concrete blocker.

## Remaining standardization work

The new campaign alpha uses individual tactical units and the country visibility authority. City/country simulation loops remain distinct consumers of common weapon/support rules. Full economy, recruitment, multiplayer authority, all weapon roles, permanent terrain scars and production-scale scheduling/instancing remain incomplete; see the campaign integration inventory. The older abstract campaign save model has not been converted.

## Forest movement ownership

packages/game-core/src/forestVehicleMovement.ts owns woodland vehicle-speed rules across the country slice and campaign travel adapters. It samples shared landscape fields rather than render instances or per-tree colliders.

## Full-continent owners

`countryDevelopedGeometry.ts` owns urban parcel surfaces for both the production scene and full-plan POI renderer. The static POI gallery exposes the same campaign town/city/metropolis planner and explicit industrial-complex configuration, with incompatible density/size/collection controls disabled. In version 3, `countrySliceScene` maintains a fine terrain index window surrounded by the coarse exterior; the authoritative lattice remains intact. Static pacing scenery retains its older fixture, as described below.

Version-3 regional composition: `countrySettlement.ts` owns ranked connected urban blocks and physical obstacles. `massiveCampaign.ts` assigns regional roles, safe anchors and satellite/scenic status; it preserves the explicit version-2 generation branch. `regionalFarmland.ts` owns regional polygons and indexed physical containment; the campaign assembler, shared `pacingRuralScene` renderer, woodland samples and armored movement consume that contract. Polygon offsets are physical local X/Z; field centers follow the caller's geographic scale. `connectedTerrain.ts` exposes bounded resolution/lowland-relief configuration with unchanged defaults for existing consumers.

`countryPOIAssets.ts` owns instanced developed plots and optional camera bounds for detailed settlements. Country/campaign scenes and static POI galleries use this same renderer; galleries request full plans, while large campaign settlements request bounded neighborhoods. `cityUnitMarkers.ts` owns grouping of already-disclosed formations; campaign enables continental clustering and group selection, while city/country tactical fixtures retain their non-clustered scale configuration. `countrySliceScene.ts` owns ranked labels, terrain-landmark labels, emplacement markers and regional street overlays. `BattlefieldApp.tsx` adapts those systems to Places search and ownership. Static pacing previews retain their explicit older compact scenery fixture; they can render the shared polygon field contract, but are not alternate version-3 campaign generators.

`campaignPhysicalScale.ts` owns the logical-to-physical conversion for both the pacing study and production campaign. `massiveCampaign.ts` assembles shared terrain, road and POI plans; it must not scale local assets. `countryLandscapeTile` in `countryLandscape.ts` owns deterministic bounded forest samples for campaign rendering, visibility and concealment. Camera residency is presentation only. `countryTravelGraph.ts` owns long road routes and physical segment safety; `countrySlice` retains shared local orders and movement. `countryObstacleIndex.ts` indexes immutable geometry snapshots; construction creates a new snapshot/index.

The shared country pose adapter clamps interpolation to its two authoritative samples; `tacticalUnitAnimation` wraps signed phases safely for every city/country/campaign consumer. Keep these corrections in the shared owners.

`countrySliceScene.ts` owns camera-dependent terrain and settlement presentation for the country harness and production campaign. Full campaign overview uses one instanced settlement-silhouette batch, a two-cell terrain index LOD and a device-pixel-ratio cap of 1. Below the strategic threshold it restores individual cullable settlement silhouettes, full terrain geometry and the detailed device ratio. Label projection and POI residency update when the camera changes; simulation, visibility and collision never consume these presentation LODs.
