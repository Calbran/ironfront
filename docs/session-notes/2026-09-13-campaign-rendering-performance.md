# Campaign rendering performance — 2026-09-13

The full-scale campaign was smooth near the detailed city but lagged at whole-map zoom. A four-second local headless-Chrome baseline measured 30.3 ms median / 36.4 ms p95 at overview, versus 6.1 / 6.2 ms in the city. Authority was not the bottleneck: 120 fixed simulation ticks measured 3.7 ms median. The strategic frame issued 394 draw calls because each generated settlement retained its own silhouette mesh.

The shared country/campaign scene now combines all strategic settlement masses into one instanced mesh while retaining individual silhouettes for close frustum culling and POI streaming. Full campaign overview uses a two-cell terrain index LOD, caps internal device pixel ratio at 1, caches label projection and residency work until the camera changes, and replaces mountain hash noise with scale-aware mipmapped grain. Soldier-scale soil work exits outside its visible range. These are presentation changes only; authoritative geography, obstacles, visibility, movement and combat are unchanged.

After rebuilding, the same benchmark measured 6.1 ms median / 6.2 ms p95 and 15 draw calls at overview, with the city unchanged at 6.1 / 6.2 ms. Mountain materials, hatching, farms, roads, settlement silhouettes and labels remained visible in the review screenshots. Clickable settlement labels now forward wheel events to the shared cursor-anchored camera controller; the browser flow verifies that camera distance changes while the pointer is over a label. Typecheck, production build, focused campaign/camera tests and the full move/build/reload/visibility browser flow passed with zero browser errors. Results remain short local samples with the 64-individual integration roster, not a sustained-load or unit-ceiling benchmark.
